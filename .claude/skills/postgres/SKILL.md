# Postgres Database Skill

When this skill is invoked, write or review database code (schemas, migrations, queries, ORM models) following the guidelines below.
Apply all rules by default. If the user provides an argument (e.g. `/postgres review`), focus on that mode.

---

## Stack

- PostgreSQL 16+ as the only supported DB. Never write code that pretends to be DB-agnostic (no SQLite shims in production paths).
- SQLAlchemy 2.x with the async engine (`sqlalchemy[asyncio]` + `asyncpg`). Never use the 1.x-style `Session`; always `AsyncSession`.
- Alembic for migrations. Never mutate schema by hand on any environment, including local.
- Use `oz_shared.postgres` for shared connection helpers when available.

---

## Schema Design

### Naming
- Tables: `snake_case`, plural nouns (`users`, `order_items`).
- Columns: `snake_case`. Foreign keys: `<referenced_table_singular>_id` (e.g. `user_id`, `order_id`).
- Indexes: `ix_<table>_<columns>` (e.g. `ix_users_email`).
- Unique constraints: `uq_<table>_<columns>`.
- Check constraints: `ck_<table>_<description>`.
- Foreign key constraints: `fk_<table>_<column>_<referenced_table>`.

### Primary Keys
- Use `UUID` primary keys generated by the application (`uuid.uuid4()`), not serial integers, for anything that will be exposed in URLs or APIs.
- Serial (`BIGSERIAL`) is fine for internal junction tables or log tables where the key is never exposed.

### Columns
- Every table needs `created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`.
- Mutable rows also need `updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()`, updated via a trigger or ORM event.
- Prefer `TIMESTAMPTZ` over `TIMESTAMP` — always store times in UTC.
- Use `TEXT` instead of `VARCHAR(n)` unless there is a genuine business constraint on length. PostgreSQL stores them identically.
- Use `BOOLEAN NOT NULL DEFAULT FALSE` rather than nullable booleans.
- Avoid `NULL` for required fields — enforce `NOT NULL` at the DB level, not only in application code.
- Use `NUMERIC` for money/financial values. Never `FLOAT` or `DOUBLE PRECISION` for currency.
- Use `JSONB` for semi-structured data, not `JSON`. Add a GIN index if you query into the document.

### Constraints
- Declare all constraints in the DB, not just in the ORM. The DB is the last line of defence.
- Foreign keys must have an explicit `ON DELETE` rule (`CASCADE`, `RESTRICT`, or `SET NULL`) — never rely on the default.
- Add `CHECK` constraints for business invariants that can be expressed as a predicate (e.g. `CHECK (amount > 0)`, `CHECK (status IN ('pending', 'active', 'closed'))`).

```sql
CREATE TABLE orders (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL REFERENCES users(id) ON DELETE RESTRICT,
    status      TEXT NOT NULL CHECK (status IN ('pending', 'shipped', 'cancelled')),
    total_cents BIGINT NOT NULL CHECK (total_cents >= 0),
    created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

## SQLAlchemy Models

- One model per file is fine, but group tightly related models in the same file (e.g. `order.py` contains `Order` + `OrderItem`).
- Use the declarative `DeclarativeBase` from SQLAlchemy 2.x. Never use the legacy `declarative_base()`.
- Annotate every column with Python types using `Mapped[T]`. This drives both the ORM and type checking.
- Mirror DB constraints in the model (`nullable=False`, `unique=True`, `CheckConstraint`) so SQLAlchemy can generate correct Alembic diffs.

```python
from __future__ import annotations
import uuid
from datetime import datetime
from sqlalchemy import CheckConstraint, ForeignKey, Text, text
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship
from sqlalchemy.dialects.postgresql import UUID

class Base(DeclarativeBase):
    pass

class Order(Base):
    __tablename__ = "orders"
    __table_args__ = (
        CheckConstraint("total_cents >= 0", name="ck_orders_total_non_negative"),
    )

    id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    user_id: Mapped[uuid.UUID] = mapped_column(ForeignKey("users.id", ondelete="RESTRICT"), nullable=False)
    status: Mapped[str] = mapped_column(Text, nullable=False)
    total_cents: Mapped[int] = mapped_column(nullable=False)
    created_at: Mapped[datetime] = mapped_column(nullable=False, server_default=text("NOW()"))
    updated_at: Mapped[datetime] = mapped_column(nullable=False, server_default=text("NOW()"))

    items: Mapped[list[OrderItem]] = relationship(back_populates="order", lazy="raise")
```

- `lazy="raise"` on all relationships by default. This forces explicit loading and prevents N+1 queries from slipping in silently. Use `selectinload` or `joinedload` at the query site when you need related data.

## Async Sessions & Connection Pool

```python
# lib/db.py
from __future__ import annotations
from collections.abc import AsyncGenerator
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine

engine = create_async_engine(
    settings.database_url,
    pool_size=10,
    max_overflow=20,
    pool_pre_ping=True,   # detect stale connections
    pool_recycle=1800,    # recycle connections every 30 min
    echo=False,           # set True only in local dev
)

async_session_factory = async_sessionmaker(engine, expire_on_commit=False)

async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with async_session_factory() as session:
        yield session
```

- `expire_on_commit=False`: prevents SQLAlchemy from expiring attributes after commit, which causes implicit lazy-loads when you access the object post-commit in an async context.
- `pool_pre_ping=True`: essential for long-running services — silently drops and replaces stale connections.
- Never share a session across requests or tasks. One session per request lifetime.

## Queries & Repositories

- All DB access lives in repository classes. No ORM queries outside repositories.
- Use `select()`, `insert()`, `update()`, `delete()` from `sqlalchemy` — never string SQL except in migrations.
- Fetch only the columns you need. Avoid `select(Model)` when you only need two fields — use `select(Model.id, Model.name)`.
- Use `scalars()` for single-column selects; `mappings()` for multi-column projections.

```python
from sqlalchemy import select
from sqlalchemy.orm import selectinload

class OrderRepository:
    def __init__(self, session: AsyncSession) -> None:
        self._session = session

    async def get_with_items(self, order_id: uuid.UUID) -> Order | None:
        result = await self._session.execute(
            select(Order)
            .where(Order.id == order_id)
            .options(selectinload(Order.items))
        )
        return result.scalar_one_or_none()

    async def list_for_user(self, user_id: uuid.UUID) -> list[Order]:
        result = await self._session.execute(
            select(Order).where(Order.user_id == user_id).order_by(Order.created_at.desc())
        )
        return list(result.scalars())
```

### Avoiding N+1 Queries
- Default `lazy="raise"` on relationships surfaces N+1 at runtime — treat these as bugs, not warnings.
- Load related data eagerly at the query site: `selectinload` for collections, `joinedload` for single relations.
- For bulk operations, always prefer a single query over a loop of single-row fetches.

## Transactions

- Use explicit transactions for any operation that writes to multiple tables or rows.
- FastAPI: the session lifespan is one request. Commit once at the end of a successful write path; roll back on error.
- For multi-step mutations, wrap in a single `async with session.begin():` block — it commits on exit and rolls back on exception.
- Never commit inside a loop. Accumulate changes and commit once.
- Use `SERIALIZABLE` isolation only when correctness genuinely requires it — it increases contention. `READ COMMITTED` (the default) is correct for most OLTP patterns when you use `SELECT ... FOR UPDATE` appropriately.

```python
async def transfer_funds(session: AsyncSession, from_id: UUID, to_id: UUID, amount: int) -> None:
    async with session.begin():
        # SELECT FOR UPDATE prevents concurrent transfers on the same accounts
        from_acc = await session.get(Account, from_id, with_for_update=True)
        to_acc = await session.get(Account, to_id, with_for_update=True)
        if from_acc.balance < amount:
            raise InsufficientFunds()
        from_acc.balance -= amount
        to_acc.balance += amount
        # session.begin() commits here automatically
```

## Indexes

- Every foreign key column needs an index (PostgreSQL does not create these automatically, unlike MySQL).
- Index columns used in `WHERE`, `ORDER BY`, and `JOIN` conditions that appear in hot queries.
- Partial indexes for queries on a subset of rows (e.g. `WHERE status = 'pending'` on a large table).
- Multi-column index column order: most selective / most filtered first.
- `GIN` index for `JSONB` columns queried with `@>` or `?` operators.
- `GIN` with `pg_trgm` for `ILIKE` / full-text search.
- Don't add indexes speculatively — each index slows down writes. Add them when a slow query is observed and `EXPLAIN ANALYZE` shows a seq scan on a large table.

```sql
-- FK index (always)
CREATE INDEX ix_orders_user_id ON orders (user_id);

-- Partial index: only index rows that need processing
CREATE INDEX ix_orders_pending ON orders (created_at) WHERE status = 'pending';

-- JSONB GIN index
CREATE INDEX ix_events_payload ON events USING GIN (payload);
```

## Migrations (Alembic)

- One migration per logical change. Never combine unrelated schema changes in one file.
- Always write both `upgrade()` and `downgrade()`.
- Migrations must be safe to run against a live production database:
  - Adding a nullable column: safe.
  - Adding a `NOT NULL` column: **unsafe** without a default or a backfill step. Use a three-step: add nullable → backfill → add constraint.
  - `ALTER TABLE ... ADD CONSTRAINT`: acquires `ACCESS EXCLUSIVE` lock — do this during low-traffic windows or use `NOT VALID` + `VALIDATE CONSTRAINT` pattern.
  - Dropping a column: safe only after the application no longer references it (deploy code first, migrate second).
  - Renaming a column: **breaking** — use add-copy-drop across two deploys.
- Run `alembic check` in CI to catch models that have drifted from migrations.

```python
# Example: safely adding NOT NULL column with backfill
def upgrade() -> None:
    # Step 1: add nullable
    op.add_column("users", sa.Column("display_name", sa.Text(), nullable=True))
    # Step 2: backfill
    op.execute("UPDATE users SET display_name = name WHERE display_name IS NULL")
    # Step 3: add constraint
    op.alter_column("users", "display_name", nullable=False)

def downgrade() -> None:
    op.drop_column("users", "display_name")
```

## Security

- Never interpolate user input into SQL strings. Always use bound parameters (SQLAlchemy's `select()` API does this automatically).
- Grant the application DB role only the privileges it needs (`SELECT`, `INSERT`, `UPDATE`, `DELETE` on specific tables). Never `SUPERUSER` or schema-altering privileges at runtime.
- Use a separate migration role with `CREATE`/`ALTER`/`DROP` privileges — the app role should not be able to alter schema.
- Never log full query text that may contain PII or secrets. Configure `echo=False` in production.
- Store passwords with `pgcrypto`'s `crypt()` or, preferably, hash in application code with `bcrypt` before inserting.

## Performance Patterns

- Use `EXPLAIN (ANALYZE, BUFFERS)` to diagnose slow queries — never guess.
- Paginate with keyset pagination (`WHERE id > :last_seen_id ORDER BY id LIMIT n`) for large tables, not `OFFSET` (which scans and discards rows).
- For bulk inserts, use `insert().values([...])` with a list, not a loop of single inserts.
- Use `RETURNING` to get inserted/updated rows back in one round trip instead of a follow-up `SELECT`.
- For reporting queries or aggregations over large datasets, consider a read replica.
- Use `pg_stat_statements` in production to identify the actual slowest queries.

```python
# Bulk insert with RETURNING
from sqlalchemy.dialects.postgresql import insert

async def bulk_create(session: AsyncSession, rows: list[dict]) -> list[uuid.UUID]:
    result = await session.execute(
        insert(Order).values(rows).returning(Order.id)
    )
    return list(result.scalars())
```

## Testing

- Always test against a real PostgreSQL instance, not SQLite. Schema features used here (UUID, JSONB, `TIMESTAMPTZ`, constraints) do not exist in SQLite.
- Use Docker (`docker run -e POSTGRES_PASSWORD=test -p 5432:5432 postgres:16`) or `pytest-postgresql` to spin up an ephemeral instance.
- Fixture pattern: create all tables once per test session, wrap each test in a transaction that rolls back — no cleanup needed and tests stay isolated.

```python
import pytest
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine, async_sessionmaker
from app.models import Base

TEST_DB_URL = "postgresql+asyncpg://postgres:test@localhost:5432/test"

@pytest.fixture(scope="session")
async def engine():
    eng = create_async_engine(TEST_DB_URL)
    async with eng.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)
    yield eng
    await eng.dispose()

@pytest.fixture
async def session(engine) -> AsyncSession:
    async with engine.connect() as conn:
        await conn.begin()
        sess = AsyncSession(bind=conn, expire_on_commit=False)
        yield sess
        await conn.rollback()
```

## What to Avoid

- No raw string SQL in application code. Migrations only.
- No `SELECT *` — always name the columns you need.
- No `OFFSET`-based pagination on large tables.
- No serial integer PKs on tables whose IDs are exposed in APIs.
- No `FLOAT` for monetary values.
- No `TIMESTAMP` without timezone — always `TIMESTAMPTZ`.
- No committing inside loops.
- No sharing a session across requests or background tasks.
- No `lazy="select"` (the SQLAlchemy default) — use `lazy="raise"` and load explicitly.
- No hand-editing the database schema outside of Alembic migrations.
- No application role with DDL privileges in production.
